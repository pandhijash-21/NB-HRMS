2. Hybrid BLoC + Riverpod State Architecture

To combine robust, deterministic event auditing with flexible reactive widget trees, the app utilizes a hybrid architecture:

State Layer Classes / Providers Responsibility
Global Shell & Auth (BLoC) AuthBloc, ThemeCubit, ApiUrlCubit, AppModuleCubit Controls authentication lifecycle, session polling (8s), login, password change, and app router refresh stream.
Bridge Layer [auth_riverpod_bridge.dart](file:///c:/Users/DELL/Desktop/dev/NB-HRMS/nb_crm_flutter/lib/features/auth/presentation/auth_riverpod_bridge.dart) Listens to AuthBloc stream and hydrates Riverpod AuthNotifier so both systems share identical state.
Feature Data (Riverpod) profileProvider, crmLeadsProvider, tasksProvider, leaveProvider Asynchronous data fetching, auto-disposal, optimistic caching, and pull-to-refresh invalidation.

3. Multi-Draft Offline Persistence Engine

Powered by [form_draft_service.dart](file:///c:/Users/DELL/Desktop/dev/NB-HRMS/nb_crm_flutter/lib/core/services/form_draft_service.dart), field personnel can draft complex forms without fear of connection dropouts:

  • Multiple Named Drafts: An engineer can maintain different drafts simultaneously (e.g. "DPR - Pier Cap P34" and "DPR - Retaining Wall R2").
  • Automatic Local Auto-Save: Input changes are debounced and saved into persistent JSON storage.
  • Midway Navigation Restoration: Leaving a screen or restarting the device automatically restores the exact in-progress draft when opening the form again.
